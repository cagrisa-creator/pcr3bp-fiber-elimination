# Notes on `main.docx`

`main.tex` (compiled to `main.pdf`) is the **canonical source** of the paper —
submit this to journals, arXiv, and HAL. `main.docx` is a courtesy Word version
for venues that require `.docx`, or for co-authors/reviewers who prefer to edit
in Word. It is generated from `main_docx_source.tex`, *not* from `main.tex`
directly, for reasons explained below.

## Why a separate `main_docx_source.tex`?

`pandoc` converts `main.tex` to `.docx` reasonably well, but three constructs in
the original source do not survive the conversion cleanly:

1. **Custom macros** (`\tr`, `\adj`, `\Hess`, `\calT`, `\calD`, `\Fz`, `\R`,
   `\C`, `\Sph`, `\eps`, `\ie`, `\eg`) — pandoc's math parser (texmath) does not
   expand user `\newcommand`/`\DeclareMathOperator` macros used *inside* math
   mode, so equations containing them render blank.
2. **Numbered cross-references** (`\ref{...}`, `\eqref{...}`) — pandoc does not
   reproduce amsthm's section-based numbering (Lemma 3.1, equation (6), ...) for
   `.docx` output, so raw labels like `[eq:Tgap]` would otherwise appear in the
   text, and theorem headers would use pandoc's own flat counter instead of
   matching the numbering used in the cross-references.
3. **A handful of OOXML-math rendering bugs specific to this LibreOffice
   installation** (used here only to *verify* the docx by rendering it to
   PDF): the `align`/`align*` environments, `\lvert...\rvert`, and `\ast` all
   produced a mojibake "¿" glyph in place of the operator, even though the
   underlying OOXML (`<m:oMath>`) generated by pandoc is valid. Installing the
   `libreoffice-math` package (missing by default in this container) fixed
   math rendering in general; the remaining three constructs were worked
   around at the source level since they may also be fragile in other
   renderers.

`main_docx_source.tex` is `main.tex` with:
- the custom macros expanded to their literal LaTeX equivalents
  (`\tr`→`\operatorname{tr}`, `\calT`→`\mathcal{T}`, etc.);
- every `\cite{key}` replaced by its resolved bracket number, e.g. `[6]`;
- every `\ref{label}`/`\eqref{label}` replaced by its resolved number, e.g.
  `Lemma 3.4`, `(11)`, taken from `main.aux` after compiling `main.tex`;
- each `\begin{lemma}[Title]\label{...}...\end{lemma}` (and `theorem`,
  `corollary`, `remark`, `observation`) rewritten as a manual bold header
  `\textbf{Lemma 3.1 (Title).}` with the same resolved number, since pandoc
  does not carry amsthm numbering into `.docx`;
- the two `align`/`align*` blocks rewritten as sequences of individual
  `\[ ... \]` equations;
- `\lvert...\rvert` replaced by plain `|...|`;
- `\ast` replaced by `\star` (renders as a five-point star rather than an
  asterisk — a harmless notational substitution, used only in the Word
  version, for the distinguished-point superscript $\phi^\star$, $s^\star$).

None of these changes affect the mathematical content; they only work around
conversion/rendering limitations. **If you edit `main.tex`, the changes must be
re-applied to `main_docx_source.tex` (or re-derived) before regenerating
`main.docx`** — the two files are not kept in sync automatically.

## Regenerating `main.docx`

```bash
# 1. Compile main.tex twice to refresh main.aux (needed only if you changed
#    numbering, i.e. added/removed/reordered equations, lemmas, or citations)
pdflatex main.tex && pdflatex main.tex

# 2. Re-derive main_docx_source.tex from main.tex (repeat the substitutions
#    described above; see the git history of this file for the exact script
#    used), then:
pandoc main_docx_source.tex -s -o main.docx --resource-path=.
```

If you don't use `libreoffice-math` to verify the output yourself, at least
open the result in real Microsoft Word once before submitting — the OOXML math
pandoc produces is standards-compliant and has rendered correctly in every case
checked here after the fixes above.
